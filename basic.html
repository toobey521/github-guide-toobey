01 入门篇 · GitHub 世界观

如果你是第一次听说 GitHub，从这里开始。用最直观的方式理解这个世界。

📍 GitHub 到底是什么？

🏠

全球最大代码托管平台

GitHub 是一个基于 Git 的代码托管网站，全球超过 1 亿 开发者在这里存放、管理和协作代码。你可以把它理解成"代码界的 Google Drive"，但功能强大得多。

🌍

程序员的社交网络

在 GitHub 上你可以关注有趣的人、给喜欢的项目点赞(Star)、复制别人的代码(Fork)、提出建议(PR)，像微博+知乎+网盘的结合体。

🧩

开源世界的基石

Linux、Python、React、Vue、TensorFlow……几乎所有你听过的知名开源项目都托管在 GitHub 上。这里是全人类共享代码智慧的地方。

📄

在线简历 & 作品集

招聘程序员时，面试官的第一件事就是看你的 GitHub 主页。你的提交记录、Star 过的项目、贡献过的仓库——都是你技术能力的证明。

🤖

你的 AI 编程助手

GitHub Copilot（基于 OpenAI）能在你写代码时自动补全；GitHub Actions 可以自动测试、构建、部署。这些都在一个平台上。

📚

免费学习资源宝库

从 Python 入门到深度学习，从算法题到系统设计——GitHub 上有海量学习资料、面试题库、开源书籍，全部免费。

📍 注册与初始化设置

1
注册账号

打开 github.com，点击 Sign up。输入用户名、邮箱、密码。邮箱需要验证（收验证码）。免费

用户名就是你的 GitHub 身份 ID，别人通过 github.com/你的用户名 找到你。建议用英文名+数字的组合，例如 alice-2025。
2
完善个人主页

点击右上角头像 → Settings → Profile。上传头像、写一段个人简介、添加你的网站或社交链接。

头像建议用真实照片或卡通头像。招聘人员看 GitHub 时，真人头像的信任度更高。
3
两步验证（强烈推荐）

Settings → Password and authentication → 开启 Two-factor authentication。你可以用手机 Authenticator 应用或短信验证。

不开启两步验证的 GitHub 账号被黑客盗取后，你的所有私人仓库代码都会泄露！
4
配置 SSH 密钥（免密推送）

打开终端/命令提示符，输入以下命令👇

# 生成密钥（一路回车即可）
ssh-keygen -t ed25519 -C "你的邮箱@example.com"

# 查看公钥并复制
cat ~/.ssh/id_ed25519.pub

# 然后去 GitHub: Settings → SSH and GPG keys → New SSH key → 粘贴
5
设置 Git 本地身份

第一次使用 Git 时需要告诉电脑你是谁👇

git config --global user.name "你的GitHub用户名"
git config --global user.email "你的GitHub邮箱"
6
认识你的个人主页

访问 github.com/你的用户名，你会看到：

📍 Repository（仓库）— 一切的基础

仓库就是一个项目的根目录，存放所有代码、文档、Issues、讨论…… 每一个"项目"就是一个仓库。

📁

公开仓库 Public

全世界任何人都可以看到、克隆(下载)、Fork(复制)。开源项目都用这种。免费。

🔒

私有仓库 Private

只有你和邀请的协作者能看到。适合商业代码或未完成的项目。免费（无限制）。

🏢

仓库所属权

仓库可以属于个人账号，也可以属于组织(Organization)。组织可以设置团队权限、多人管理。

📐

仓库模板 Template

你可以把自己的仓库设为模板，别人用它一键创建同样结构的新项目。

仓库名称 命名规则

例如 awesome-python、my-first-repo。命名建议用英文小写+连字符，语义清晰。

仓库描述 Description

在仓库名下方的一行文字，告诉访客这个项目是做什么的。例如"一个帮你管理日常任务的 Python 工具"。

Topics 标签分类

给仓库打标签，比如 python、machine-learning、react，方便被搜索到。

仓库网址 URL

格式：github.com/用户名/仓库名。例如 github.com/torvalds/linux 是 Linux 内核。

▼ 标准 Pull Request 流程
PR 标题与描述 说明你的改動

标题简洁概括（如"修复登录页闪退问题"），描述详细说明改动原因、改了什么、如何测试。

Conversation 讨论区

审查者可以针对每一行代码发表评论。发起者需要在讨论中解释或修改。

Commits PR 内的提交

一个 PR 可以包含多个 Commit。每次 Push 新代码都会自动追加到这个 PR 中。

Checks 自动检查

Actions 自动运行测试/构建，检查通过（绿色✓）才能合并，防止坏代码进入主分支。

Merge 方式 三种策略

Create a merge commit（保留完整历史）/Squash and merge（压缩成一个提交）/Rebase and merge（线性历史）

Draft PR 草稿模式

代码写到一半时创建 Draft PR，告诉别人"还在建设中，请先别合并"。完成后点击 Ready for review。

📍 LICENSE & .gitignore — 两个重要的配置

📜

LICENSE（许可证）

开源不等于"随便用"。许可证告诉别人：能不能商用？要不要署名？改了的代码要不要也开源？常见的许可证：

MIT 最宽松，随便用 Apache 2.0 宽松+专利保护 GPL 必须开源 BSD 类似 MIT
🚫

.gitignore（忽略文件）

有些文件不应该上传到 GitHub：

  • 📁 node_modules/ —— Node.js 依赖包
  • 🔑 .env —— 环境变量/密码
  • 🖼 *.log —— 日志文件
  • ⚙️ .idea/ —— IDE 设置
  • 📦 __pycache__/ —— Python 缓存

在 .gitignore 文件里写一行一个规则，Git 就会自动忽略这些文件。

🌿

默认分支 (Default Branch)

早期 GitHub 默认分支叫 master，现在是 main。这是仓库的主干，所有最终发布的代码在这里。

📝

仓库可见性切换

公开→私有：已有的公开仓库可以改为私有，但 Fork 过的副本不会自动同步。
私有→公开：确认没有敏感信息后即可切换。

分支 (Branch) 并行开发

分支让你可以"平行宇宙"式开发——在 dev 分支写新功能，同时在 main 分支修 Bug，互不影响。最后再将 dev 合并到 main。

⚡

分支保护 防误操作

设置中可开启 Branch Protection：禁止直接 Push 到 main 分支、要求 PR 审查通过、要求 Actions 通过。

📍 Commit（提交）— 每一次改动的快照

Commit 是 Git 的核心概念——每次 Commit 就像是给整个项目拍了一张"快照"，记录了这一时刻所有文件的样子。

Commit SHA 唯一标识

每个 Commit 都有一个 40 位的十六进制哈希值（如 a1b2c3d4e5f6...），全球唯一。也可以只用前 7 位来引用。

提交信息 (Commit Message) 写清楚改了啥

好的格式：第一行标题（50字内）+ 空行 + 详细描述。例如：
feat: 添加用户登录功能
修复了当用户输入空密码时的崩溃问题

作者 Author 谁改的

显示姓名 + 邮箱 + 时间。跟 GitHub 账号关联后，头像也会显示。

绿点+红点 改了什么

Commit 详情页显示 + 绿色（新增）和 - 红色（删除）的代码 diff。

parent 父提交

每个 Commit 指向它的前一个 Commit，形成一条"链"。Merge 提交有两个 parent。

Commit 在 Git 中是不可变的！一旦提交，历史就不能篡改（除非强制重写，但会被认为是危险操作）。这保证了代码审查的可追溯性。

📍 SSH 密钥 & Token — 安全连接

GitHub 提供了多种方式来验证你的身份，避免每次操作都输入密码：

方式优点设置难度推荐场景
SSH 密钥一次设置，永久使用；更安全⭐⭐ 中等个人电脑（开发者首选）
Personal Access Token (PAT)灵活，可设置过期时间和权限⭐ 简单脚本/CI/临时访问

1
Fork 原仓库

打开你想贡献的 GitHub 仓库 → 点击右上角 Fork 按钮。现在你的账号下有了一个一模一样的副本。

Clone 到本地

git checkout main

▼ Git Flow 经典分支模型（适合中大型团队）
策略复杂度适合场景
Git Flow⭐⭐⭐ 高大型团队、有版本规划的项目（如软件产品）
GitHub Flow⭐ 低小型项目、持续部署（每个 PR 上线就是一次发布）
主分支开发⭐ 最低个人项目、实验性项目
GitHub Flow 是 GitHub 官方推荐的方式：只有一个 main 分支，所有开发都在 feature 分支上完成，通过 PR 合并到 main。简单、高效、适合大多数项目。
▶ 了解 GitHub Flow 详细步骤
  1. 从 main 分支创建一个 feature 分支（git checkout -b feature-xyz）
  2. 在 feature 分支上提交修改
  3. 推送到 GitHub（git push origin feature-xyz）
  4. 创建 Pull Request
  5. 讨论、审查、修改
  6. 合并到 main 分支
  7. 自动部署（如果有 CI/CD）
▶ 学会查看别人仓库的 CONTRIBUTING.md

几乎所有大型开源项目都有 CONTRIBUTING.md（贡献指南），里面写了：

  • 如何报告 Bug（模板）
  • 代码风格要求
  • 测试要求
  • PR 提交规范
  • 行为准则（Code of Conduct）

在提 PR 之前，一定要先读 CONTRIBUTING.md！很多新手 PR 被拒的原因就是没看贡献指南。

项目站点 每个仓库都有

免费 HTTPS

GitHub Pages 自动为你的站点签发 Let's Encrypt 证书。即使使用自定义域名也支持 HTTPS。

🎨

主题选择

GitHub Pages 提供多款 Jekyll 主题（Minima、Cayman、Slate 等），在 Settings → Pages → Change theme 一键切换。

07 GitHub Actions · 自动化流水线

Actions 是 GitHub 的 CI/CD（持续集成/持续部署）工具，让机器帮你做重复劳动。

flowchart LR A["📤 代码 Push"] --> B["⚡ 触发 Workflow"] B --> C["🔧 Job 1: 安装依赖"] C --> D["🧪 Job 2: 运行测试"] D --> E["📦 Job 3: 构建"] E --> F["🚀 Job 4: 部署"] F --> G["🌐 网站上线"] B --> H["🕐 定时触发

▼ 一个典型 CI/CD 工作流的触发→执行→部署链
🤖

Workflow（工作流） .github/workflows/

用 YAML 文件定义自动化流程。文件放在仓库的 .github/workflows/ 目录下。每次 Push、PR 或定时触发时自动运行。

🧩

Marketplace 预制 Action

GitHub Marketplace 上有成千上万个别人写好的 Action 可以直接用：
- actions/checkout —— 拉取代码
- actions/setup-python —— 配置 Python
- peaceiris/actions-gh-pages —— 部署到 Pages

🔐

Secrets（密钥） 安全存储

Settings → Secrets and variables → Actions。你可以存 API Key、密码等敏感信息，Workflow 中用 ${{ secrets.MY_KEY }} 引用。

⏱️

定时任务 Cron 触发

Workflow 可以定时运行，比如每天凌晨自动爬取数据、每周生成报表。
schedule: - cron: '0 8 * * *'（每天早上8点）

🏃

Runner（运行器）

Workflow 在 GitHub 提供的免费虚拟机上运行（Linux/Windows/macOS）。免费额度：每月 2000 分钟。

⚡

Matrix Build 多版本并行

一键测试多个环境：Python 3.9/3.10/3.11 + Ubuntu/Windows/macOS 并行运行，一个配置搞定所有。

一个最常用的 Action 示例：每次 Push 时自动运行 pytest 测试，测试通过后自动部署到 GitHub Pages。你只需要在 .github/workflows/main.yml 写不到 30 行 YAML 配置。

12 FAQ · 常见问题

新手最常问的问题，全部在这里解答。

▶ GitHub 是免费的吗？
✅ 是的，个人使用完全免费！免费版包括：无限量的公开和私有仓库、2000 分钟/月的 Actions 运行时间、500MB 的 Packages 存储空间。付费版（Team/Enterprise）提供更多高级功能（如更高级的代码审查、合规功能），对大多数个人用户完全不需要。
▶ 我不会写代码，用 GitHub 有用吗？
非常有用！即使你不会写代码，GitHub 也可以：
— 存放和管理你的文档（用 Markdown 写作）
— 搭建免费的博客/网站（GitHub Pages）
— 下载和学习别人的项目
— 用 Issues 做任务管理
— 参与翻译类开源项目
— 学习技术写作和协作流程
▶ 不小心把密码提交到公开仓库了怎么办？
⚠️ 立即行动！
1️⃣ 立刻更改密码/密钥（去对应的网站重新生成）
2️⃣ 用 git rm --cached 从仓库移除文件
3️⃣ 建议强制删除 Git 历史中的敏感信息（使用 git filter-branch 或 BFG Repo-Cleaner）
4️⃣ 如果有推送，GitHub 可能已经检测到并通知你
✅ 重要的是：从 Git 历史中彻底清除（不仅仅是删文件），因为敏感的提交仍在历史里。
▶ 如何删除一个仓库？
Settings → Danger Zone → Delete this repository。输入仓库名确认。⚠️ 这个操作不可逆！删除后所有 Issues、PR、Wiki 全部丢失。如果只是想隐藏，可以改为私有（Private）。
▶ 什么是 Merge Conflict（合并冲突）？怎么解决？
当两个人同时修改了同一个文件的同一行代码时，Git 不知道该保留谁的——这叫做"冲突"。解决方式：
1️⃣ 用 git status 查看哪些文件有冲突
2️⃣ 打开冲突文件，你会看到：
<<<<<< HEAD
你的改动
=======
别人的改动
>>>>>> 分支名
3️⃣ 手动保留需要的代码，删除冲突标记
4️⃣ git add → git commit 完成解决
▶ Fork 和 Clone 的区别是什么？
Fork：在 GitHub 网站上操作，把别人的仓库复制到你的 GitHub 账号下。Fork 后的仓库与原仓库有关联（可以提 PR）。
Clone：把 GitHub 上的仓库下载到你本地电脑。Clone 可以是自己的仓库，也可以是别人的。

✅ Fork 在云端创建一个副本，Clone 在本地创建一个副本。通常流程是：先 Fork，再 Clone 你的 Fork 到本地。
▶ 什么是 gitignore？为什么重要？
.gitignore 告诉 Git 哪些文件不需要跟踪（上传到 GitHub）。重要原因：
— 🚫 避免上传密码、密钥、Token
— 📦 避免上传第三方依赖（如 node_modules）
— ⚙️ 避免上传 IDE 配置文件
— 🖼️ 避免上传临时文件/日志
GitHub 创建仓库时提供了常用语言的 .gitignore 模板，可以直接选用。
▶ 怎么给开源项目做贡献？
不用一上来就写代码！开源贡献有多种方式：
⭐ 修文档：修正拼写错误、补充使用说明
🐛 测试并报告 Bug：认真描述如何复现问题
💬 在 Issues 里帮助回答别人
🌍 翻译：把项目文档翻译成中文
🧪 写测试：提高项目代码质量
📝 完善 README：好的文档对项目非常重要
🔧 修复 Good First Issue：搜索 label:"good first issue"
▶ 我提交了 Commit，但想撤回怎么办？
分情况：
— 还没 Push：git reset --soft HEAD~1（保留修改，撤销 Commit）或 git reset --hard HEAD~1（彻底撤销，慎用）
— 已经 Push：git revert HEAD 创建一个"反向"提交，保留历史
— 如果 Push 到公共分支：不要用 reset，必须用 revert！因为 reset 会改写历史，别人已经 Pull 了你的代码就乱套了。
▶ 什么是 GitHub Gist？
Gist（gist.github.com）是一个轻量级的代码片段分享服务。你可以：
— 分享一段代码给别人看
— 存放常用的小脚本
— 做笔记（支持 Markdown）
— 创建秘密 Gist（只有知道链接的人能看到）
Gist 有自己的 Git 仓库，可以 Clone 到本地管理。
▶ 为什么我的仓库里没有绿色小方块（贡献图）？
几个可能原因：
1️⃣ 你没有登录 GitHub 时提交——Commit 的 author email 必须关联到 GitHub 账号
2️⃣ 你在私有仓库中提交——默认私有仓库的提交不显示在贡献图上，需要在贡献图设置里开启
3️⃣ 你 Fork 了别人的仓库——Fork 后的提交默认不显示
4️⃣ 你的提交在非默认分支——只有默认分支的提交算贡献
▶ 什么是 Git rebase？和 merge 的区别？
git merge：创建一个新的"合并提交"，把两个分支的历史连接起来。保留了完整的历史，但会让分支图变复杂。
git rebase：把你的提交"移植"到另一个分支的顶端，使历史变成一条直线。更干净，但会改写历史。

常用原则：
— 公共分支（main）——用 merge，保持历史可追溯
— 自己的功能分支——用 rebase 让提交历史更整洁
▶ 如何在 README 里显示图标/徽章？
用 Shields.io 生成各种徽章：

![Stars](https://img.shields.io/github/stars/用户名/仓库名)

Shields.io 提供上千种徽章：构建状态、测试覆盖率、代码质量、下载量……让你的 README 更专业。
▶ 如何把本地已有的项目上传到 GitHub？ 
# 在 GitHub 上先创建一个空仓库（不要勾选 README）

# 本地项目目录下
git init
git add .
git commit -m "initial commit"
git branch -M main
git remote add origin https://github.com/你的用户名/仓库名.git
git push -u origin main
▶ GitHub 有没有容量限制？
有，但对个人使用很充裕：
— 每个仓库推荐不超过 1GB（硬限制 5GB）
— 单个文件最大 100MB（超限会警告）
— 超过 50MB 的文件建议用 Git LFS（大文件存储）
— Git LFS 免费额度：2GB 存储 + 1GB/月带宽
▶ 我想参与开源，但英语不好怎么办？
不要被英语吓倒！很多国内项目有中文社区：
— 搜索中文 Issue 或 Discussions
— Vue、Ant Design 等国内优秀项目全程中文
— 在项目 Issues 里用中文提问（大部分中国开发者接受中文）
— 国际项目也可以看中文翻译版文档
— 不过，提升英语对编程非常有用，建议逐步适应英文交流
